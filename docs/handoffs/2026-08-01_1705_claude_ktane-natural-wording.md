## 1. 何が起きていたか

実機で2つの報告があった。別々の症状に見えるが、**同じ設計ミス**から出ている。

| 報告 | 実際の原因 |
|---|---|
| 「決まったキーワードを毎回言うのは難しい。人によっても言い方は変わる」 | 記号の照合が**呼び名の文字列一致**だった |
| 「長押しとか押すとかの表現が通じず、push / hold と英語表記でないと伝わらない」 | ボタンの文字の語彙から「押す」を**外していた**／聞き返しが**英語**だった |

共通の間違いは、**こちら側が正解の言い方を持っていると仮定したこと**。
キーパッドの記号には公式の読み方が無く、ボタンの文字は日本語で言うのが自然。
どちらも「利用者が決める」側の情報なのに、辞書と一致するかで判定していた。

## 2. 直し方の方針

**衝突する語を捨てるのではなく、意味の取り方を分ける。**

これが今回いちばん重要な判断で、14:30 の修正で一度踏み外している。
「押す」が動詞と紛れるという理由で語彙から外した結果、
**いちばん自然な言い方だけが通らない**という歪んだ挙動になった。
語を捨てる修正は、安全に見えて実は「使えない機能」を作る。

代わりに、**その語が文字として言われた場面かどうか**で分ける。

## 3. 記号の照合（16:10）

`symbols.py`

- `FEATURES`: 28 の**形の特徴**群。丸・線・三本・星・稲妻・しっぽ・逆・曲・
  四角・三角・十字・はてな・数字・アルファベット・プサイ・オメガ・水滴 ほか
- `features(text)`: 説明から特徴を拾う。**知らない言葉は捨てる**
- `_similarity()`: **特徴の重なりを先に**見て、文字列一致は保険。
  言われた特徴が全部含まれていれば、説明が短くても当たり（score .8 以上）
- `match_symbol(accept=.5, margin=.12)`: 1位と2位が近すぎれば `ambiguous` で返し、
  呼び出し側が聞き返す
- `SymbolVocabulary`: 言われ方を覚える。**特徴が同じものは覚えない**
  （「稲妻」と「いなずま」——既に照合できるものを溜めても表が膨らむだけ）

| 言い方 | 届く記号 |
|---|---|
| 丸に線 / 円の中に横棒 / まるにぼう / 丸くて線が入ってるやつ | 丸に線 |
| ぎざぎざの線 / 雷みたいなの | 稲妻 |
| Cが裏返ってる / 反対向きのシー | 逆さのC |
| しずくみたいな形 / 涙のかたち | 水滴 |

**寄せない側**: 「なんかすごい形」は特徴が0なので照合しない。
曖昧なものを確定させると隣の記号を押させて即ミスになる。

## 4. ボタンの文字（17:05）

`parse.py` の `parse_button_label(text, *, expected=False)`

語彙を2段に分ける。

1. **動詞と紛れない言い方** — いつ出てきても採る
   `abort / アボート / 中止 / 中断 / detonate / デトネート / 起爆 / 爆破 /`
   `hold / ホールド / 保持 / press / プレス / push / プッシュ`
2. **動詞としても普通に出る言い方** — 場面が合う時だけ採る
   `長押し / ながおし / 押しっぱなし / 押し続け / 押す / 押せ / おす`

2 を採る場面は2つ。

- `_READING_LABEL`: 「〜って書いてある」「文字は」「ラベルは」「表示されてる」
- `expected=True`: **直前にこちらが文字を尋ねた**（`expert.slots["asked_label"]`）。
  尋ねた直後なら発話まるごとが答えなので、「長押し」の一言で通る

**採らない場面**: `_PRESSED_REPORT`（「押したよ」「押しました」「長押ししてみた」
「押しといた」）。これは押した報告であって文字ではない。ここを採ると、
押し終わった後に別の指示が確定する。尋ねた直後でも採らない。

`expert.py` の聞き返しは日本語を先に置いた。

> ボタンに書いてある文字（中止 / 爆破 / 長押し / 押す のどれか。英語なら Abort / Detonate / Hold / Press）

**聞き方が答え方を決める。** 英語で列挙していたことが報告の半分の原因だった。

`rulebook.py` にも対応表と「英語で言い直させない」を追記した。
ポッポ自身が規則を読んで考える経路の手当て。
