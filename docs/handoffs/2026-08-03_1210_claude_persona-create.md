## 1. 何が出来なかったか

`apply_persona()` は `presets` に無いキーを `未定義のペルソナ` で弾く。
既存の `_persist_yaml_value()` は**行の置換**しかできず、無い鍵は書けない。
つまり**新しいペルソナは `config.yaml` を手で編集するしかなかった**。

## 2. どう足したか

`_persist_yaml_new_preset()` — `persona.presets` の末尾へブロックごと挿す。

**`yaml.dump` でファイル全体を書き直していない。** それをやると
`config.yaml` のコメントが全部消える。あのコメントは設定の説明そのもので、
ペルソナを1つ足すたびに失うのは割に合わない。

API は `create_persona({key, name})`。GUI のペルソナタブに
「新しいペルソナを追加」を置いた。

## 3. 決めたこと（理由つき）

- **キーは `^[a-z][a-z0-9_]{0,31}$`。** これは飾りではなく、
  `mind_<key>.db` `relationships_<key>.json` などの**ファイル名になる**。
  `..` や `/` を通すと別のペルソナのファイルを指せる。
- **中身は空で作る。** 既存プリセットから写すと、新しいペルソナが
  最初から他人の口調と設定を持つ。後から「なぜこの喋り方なのか」が
  追えなくなる。空欄は System Prompt に含まれないので実害はない。
- **追加しても切り替えない。** `persona.active` を触らない。
  作った直後に切り替えると、記憶も関係値も空の人格へいきなり
  入れ替わる。内容を書いてから「適用」を押す方が取り消しが効く。

## 5. 追記（12:40）: 最初の版の不具合

チビが実機で見つけた。**追加した直後のペルソナで「適用」を押すと
「config.yaml への保存は一部失敗」**と出る。

原因は、新規プリセットに `conversation_traits` の行を書いていなかったこと。
`apply_persona()` は `_persist_yaml_mapping()` でその行を**書き換える**が、
無い鍵は書けないので False が返り、`saved = False` になっていた。

**型のテストは26件全部通っていた。** 作る所と書き換える所を別々に見て
いて、往復させていなかった。`turn_tracker` の時と同じ形で踏んだ:
「実装がある」と「効いている」は違う。

修正しながら同種のもう1件も見つけた——`PERSONA_FIELDS` の項目を
呼び出し側が渡し忘れると、その行が丸ごと欠けて同じ症状になる。
`_persist_yaml_new_preset()` の側で**必ず全部書く**ようにした。

追加したテスト2件は、作った直後のプリセットに対して
`apply_persona()` が触る鍵を**実際に書き戻す**。

### 既に追加してしまったペルソナがある場合

`config.yaml` の該当プリセットへ1行足せば直る:

```yaml
    <キー>:
      name: ...
      conversation_traits: {}     # ← これを足す
      system_prompt: |
```

作り直しても同じ。

## 6. 追記（13:10）: 削除を追加

`delete_persona()` と GUI の「選択中のペルソナを削除」。

**`config.yaml` の一覧から外すだけ。`data/` のファイルには触らない。**

理由は、消すと戻せないから。設定を1つ消したつもりで、そのペルソナと
話した記録（`mind_<key>.db`・関係値・人格・時間感覚）が全部無くなるのが
いちばんまずい。一覧から外すだけなら、**同じ ID で作り直せば記憶も戻る。**

消さない代わりに、**残っているファイル名を返して画面へ出す。**
消せないことと、知らせないことは違う。本当に消したい時は、それを見て
`data/` から手で消せる。

拒否する条件は2つ。どちらも削除の**前**に判定する。

* **使用中のペルソナ** — 今まさに喋っている人格が消えることになる
* **最後の1つ** — 選べるものが無くなる

### 故障注入（4種）

| 戻したもの | 赤くなった件数 |
|---|---|
| 記憶ファイルも消す（`shutil` を入れる） | 1 |
| 使用中/最後の判定を削除の後ろへ動かす | 1 |
| ブロックの範囲を1行だけにする（中身が残る） | 2 |
| 残ファイル一覧から1つ抜く | 1 |

最後のは `mind.py` の `f"..._{key}.json"` を正規表現で拾って
`PERSONA_DATA_PATTERNS` と突き合わせている。**`mind.py` 側に
ペルソナ別ファイルが増えた時に気づける。**

## 7. 残っていること

- **削除・複製・リネームは無い。** 削除は `mind_<key>.db`・関係値・
  personality・temporal など**ペルソナごとのファイル一式**をどうするか
  （消す／残す／退避する）を決める必要があり、追加よりずっと重い。
  消して戻せないのがいちばんまずいので、今回は手を出していない。
- **GUI の見た目は実機未確認。** 追加ボタンの位置と、追加後に一覧が
  更新されるかはチビに見てもらいたい。
- 追加したペルソナで初めて会話すると、そのタイミングで
  `data/mind_<key>.db` などが作られる。
