## 1. 何が問題だったか

関係値は `relationships_<key>.json` と、**ファイル名では分かれていた**。
だが中身に持ち主が書かれていない。

名前だけの分離は、次のどれかで崩れる:

- バックアップから別名で復元する
- ペルソナを削除して同じ ID で作り直す
- ファイルを手でコピーする

そして**崩れても気づけない。** 別のペルソナのなかよし度が、そのまま
新しい人格の「初対面のはずの相手への親しさ」になる。

## 2. 直したこと

保存時にヘッダへ持ち主を書く。

```json
{"schema_version": 2, "persona_id": "poppo", "relationships": {...}}
```

読み込み時に持ち主が違えば**読まない**。そして——ここが肝心だが——
**`save()` も止める。**

読まないだけにして書き込みを許すと、次の保存が**相手の関係値を
空で上書きする。** 読めないのは「覚えていない」で済むが、
消えるのは戻せない。

持ち主の無い旧ファイルは、そのペルソナが**引き取る**。
ファイル名で既に分かれているので、これは配布ではない。冪等——
一度ヘッダが付けば二度目は引き取りにならず、**別のペルソナが同じ
ファイルを引き取ることもできない。**

`persona_id` を渡さない呼び出しは**従来どおり素通し**。既存経路を
壊さないため。

## 3. チビの環境で何が起きるか

いまの `data/relationships_*.json` は schema 1・持ち主無し:

```
a     0件
b     2件
neuro 7件
```

次回起動時に、それぞれのペルソナが自分のファイルを引き取る。
**値は動かさないので、なかよし度は失われない。** 挙動が変わるのは、
ファイルがペルソナ間で入れ替わっていた場合だけで、その時は
読まずに警告が出る。

取り消したくなったら `rollback_adoption()`——値は動かしていないので、
ヘッダを消すだけで元に戻る。
