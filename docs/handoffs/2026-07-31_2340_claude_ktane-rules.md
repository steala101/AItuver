## 追記（2026-08-01 01:00）— 同じ質問しか返らなくなる不具合

実機で「ボタンの色と、書いてある文字を教えて。」ばかり返る状態になった。

- 原因: **`current_module` は言い直すまで残る**。一度「ボタン」と言われると
  以後の発話がすべてボタンの判定へ入る。そこが**手がかりゼロの発話にも
  必ず質問を返していた**ので、「シリアルはA1B2C3」と言っても同じ一文が返った
- 直したもの:
  - 色も文字も無い発話は `None` を返して会話側へ渡す
  - 片方だけ分かっているときは**足りない方だけ**聞く
  - `_without_repeating_itself()` を経路の出口に置き、**同じ質問を2回続けて
    返さない**。今回はボタンで露出したが、モジュールが増えれば同じ壊れ方は
    再発しうる
- **ついでに危険な誤読を1つ潰した**: 「押す」をボタンの文字（Press）の別名から
  外した。普通の動詞として頻出するので、「青いボタンを押すね」で `label=press`
  と読み、**条件を1つ飛ばして間違った指示を確定させる**ところだった

### 新しい分担

1. 扱っているモジュールの規則を `rulebook.py` からプロンプトへ渡す
2. ポッポが自分で読んで考え、自分の言葉で答える
3. コードは独立に同じ問題を解き、`pending_check` として抱えておく
4. **発話の前に**突き合わせる（`verify.py`）

判定は3値。

| 判定 | 動き |
|---|---|
| `AGREE` | ポッポの言葉のまま話す |
| `DISAGREE` | コードの答えへ差し替える |
| `UNCLEAR` | **触らない**。記録だけ残す |

3つ目が一番大事。「2本目か3本目だと思う」のように結論が2つ出ている発話を
どちらとも決めつけない。**読めなかっただけで正しいかもしれないのに
差し替えるのは、それ自体が誤り**である。

### 間違った指示は耳に届かない

セッション中は全文を保持してから発話する経路（`activity_guarded`）が
既にあったので、それに乗せた。Discordは既定で文単位に流すため、
検算が要るターンだけ保持する側へ入れた（第19条）。

差し替え文は「んー……ちょっと待って。ここは2本目を切って。3本で赤が
無いときだから」という形。自分で気づいて言い直した体にしてある。
黙って別のことを言うと、聞いている側が何が起きたか分からない。
