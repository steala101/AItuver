# Discord 再生停止・遅延再生バグ 修正記録

## 症状
疑似フルデュプレックス実装後、Discord通話で「AI音声が急に流れなくなる →
数回応答しても無音 → かなり後で最初の古い音声からまとめて流れ出す」。

## 根本原因 (実際に競合していたイベント順)

```
AI発話中にユーザー音声/エコー候補を検出
→ soft interrupt で encoder を pause (_barge_paused=True)
→ pause中にAIの現在の応答が「自然終了」する
→ その後 _handle_utterance が STT を確定
→ このとき assistant_audio_active が False になっている
   (AI音声が終わっているため)
→ pauseを解除する分岐 (相槌/誤検知/割り込み) が「全てスキップ」される
→ _barge_paused=True・encoder=paused のまま新しい応答を生成
→ 新応答の音声(有効な世代)を「停止中の encoder」へ play_pcm
→ 再生されずサイドカーのバッファに溜まる
→ soft-interrupt watchdog が数秒後に resume
→ 溜まっていた古い音声が遅れて流れ出す (以降ずれ続ける)
```

- pauseの呼び出し元: `_on_discord_speech_start`(最初のPCMパケット/VAD開始)。
- resumeの呼び出し元: 相槌/誤検知/エコー/自己エコー/watchdogタイムアウト、
  ハード割り込み時の `_cancel_discord_response`。
- **pause timeout は単一のwatchdogループ**(per-pauseのasyncioタスクを作らない設計)
  なので「タイマー増殖」は無し。問題は上記の**pause取り残し**だった。

## 修正 (非同期状態・世代管理の解消)

1. **新応答開始時に再生をリセット**(指示書§17)—
   `_reset_playback_for_new_response()` を `_handle_utterance` の応答生成直前と
   `_run_proactive_turn` の開始時に必ず呼ぶ。pauseが残っていれば解除し、
   `_tts_source.discard_paused_audio()` とサイドカーの `stop_playback()` で
   **溜まった古い音声を破棄**してから新応答を再生する。→ 遅延再生を根絶。
2. **pause_token**(指示書§7)— pauseごとに採番。resume は token を照合し、
   その後に発行された新しい pause を古い timeout/判定が解除できないようにする
   (watchdog の自動resumeは採番時のtokenを渡す)。reset時も token を進める。
3. **世代検証**(既存)— `_speak` は `_is_response_active(response_id)` で
   古い応答の音声を送信前に破棄。今回のresetと合わせ、古い世代は再生されない。
4. **PAUSED中の再pauseは冪等**— `_on_discord_speech_start` は
   `if self._barge_paused: return` で二重pause/二重timeoutを作らない(既存)。

割り込み・相槌・エコーガード・発話終了判定の挙動は変更していない。

## テスト
`tests/test_playback_pause.py`(pause_token/reset/世代破棄の不変条件、指示書の
再現テスト1・2・4・5相当)4件パス。bot.py 全編集部の構文OK。

## 残る確認 (実機)
実際のDiscord通話で、長話中に相槌/咳/「待って」を混ぜ、10回以上・5〜10分の
継続で「音声消失なし・古い音声の遅延再生なし・キュー/タスク非増殖」を確認する
(指示書§20)。ログは `FD ` / `再生をリセット` / `古いresumeを無視` で追える。
