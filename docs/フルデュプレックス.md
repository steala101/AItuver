# 疑似フルデュプレックス (フェーズ1+2)

AIが話している間もユーザーの声を聞き続け、明確な割り込みには素早く反応し、
相づち・ノイズでは止まらない会話を、既存のSTT/LLM/TTSの上の会話制御レイヤーで
実現する(音声ネイティブモデルは使わない)。

## 現在の実装状態

もともとDiscord経路(DAVE直接受信)には次の土台があった:

- AI発話中も受信・VAD・STTは継続(受信は止まらない)
- 最初の音声パケットで再生を**一時停止**(=ソフト割り込み。停止ではない)
- STT確定後に分類: 相づち/誤検知→**再生再開**、実質発話→**ハード割り込み**
- `response_id`による世代管理(キャンセル後の古い音声・トークンは破棄)
- `PlayedTextTracker`が発話済み/未発話テキストを区別し履歴へ反映
- TTSは文単位チャンク(≤30字)、未再生キュー破棄・LLMタスクcancel実装済み

フェーズ1+2で追加したもの:

1. **ソフト割り込みタイムアウト** — pause後、`soft_interrupt_timeout_ms`(既定1500ms)
   までに判定が確定しなければ再生を自動再開。咳・ノイズでSTTが空になっても
   AIが黙り込まない(取り残し防止)。発話継続中・発話確定処理中は自動延長。
2. **割り込み語の即断(interim)** — 「待って」「ストップ」「止めて」等の強い語を
   **STT途中結果**で検出した時点で、発話確定を待たずにハード割り込み。
   体感の停止が1〜2秒速くなる。
3. **割り込み語の確定オーバーライド(final)** — 「違う」「いやいや」「訂正」等の
   短い発話が相づち/誤検知に分類されて飲み込まれるのを防ぎ、確定的に割り込み扱い。
4. **計測ログ** — `FD pause_to_resume: 340ms (reason=...)` /
   `FD pause_to_interrupt: 820ms (reason=keyword_hard_interrupt)` /
   状態スナップショット(`FD state: input=... output=... reasoning=...`)。
   `logs/neuro_voice.log` で「FD 」を検索。

## 設定 (config.yaml)

```yaml
full_duplex:
  enabled: true                     # false=全て無効(従来動作へ完全に戻る)
  soft_interrupt_timeout_ms: 1500   # pause自動再開までの猶予
  keyword_interrupt_enabled: true   # 割り込み語の即断/オーバーライド
  extra_interrupt_words: []         # 追加の即断語。STTの表記(漢字含む)で書く
```

## 調整の目安

- **誤停止が多い** → `extra_interrupt_words`を減らす / `keyword_interrupt_enabled: false`
  で語彙即断だけ無効化(既存の実質発話分類は生きる)。
- **割り込みを見逃す** → よく使う言い回しを `extra_interrupt_words` へ追加
  (例: `["ぽっぽ止まれ"]`)。カタカナ・全半角・空白の揺れは自動で吸収、漢字は表記どおり。
- **AIが黙り込む/途切れる** → `soft_interrupt_timeout_ms` を短く(例: 1000)。

## フェーズ4: 相づち判定の高度化 (実装済み)

- **複合相づち**: 「うんうんそうそう」「なるほどね、うんうん」のように、既知の
  相づち+フィラー+語尾だけで構成される発話は相づち扱い(再生継続)。
  「うん、でもさ」のように内容語が続く場合は従来どおり割り込み(発言権の主張)。
- **笑い声**: 「ははは」「あはは」「www」「笑」等は誤検知扱いで再生継続
  (以前は実質発話として割り込みになっていた)。

## フェーズ5: 音響エコーガード (実装済み)

Botが送信したTTS音声の**エネルギー包絡**(20ms RMS・50Hz)を直近6秒ぶん保持し、
受信したユーザー音声の包絡と全オフセットで相関を取る。スピーカー回り込み
(=AIの声がユーザーのマイクへ戻った音)は抑揚パターンが一致するため高相関になる。

- 相関が `similarity_threshold`(既定0.78)以上 → 回り込みとして破棄+再生再開。
  スコアと理由をログに記録(`FD echo-guard: 音響類似0.85≥0.78 → …`)。
- **明確な割り込み語がある場合はエコーガードより割り込みを優先**(回り込み中でも
  「待って」は通る)。
- テキスト類似ガード(従来からある `自己エコーを破棄`)も併用。どちらで破棄しても
  pauseを解放するため、回り込みでAIが黙り込まない。
- 音量やコーデックの違いに強い対数包絡+ピアソン相関で、生波形の厳密な
  エコーキャンセルは行わない(指示書15章の「現実的なガード」方針)。

調整: 誤破棄(本物の発話がエコー扱い)が出る場合は `similarity_threshold` を
0.85 へ上げる。回り込みで止まる場合は 0.7 へ下げる。`enabled: false` で無効化。

## フェーズ6: 発話終了判定の動的化 (実装済み)

固定の無音時間(0.65〜0.7秒)だけでターン終了を決めず、**STT途中結果の語尾**で
待ち時間を動的に調整する(両受信経路対応):

- 「〜けど」「〜で」「えっと」「うーん」等の**接続・思考語尾** → 考え中と判断し
  +700ms待つ(ユーザーの話を奪わない)。
- 「〜です」「〜?」「〜お願い」等の**文末表現** → -150msで早めに応答。
- それ以外は従来どおり。上限2.5秒/下限0.3秒でクランプ。

設定: `full_duplex.endpoint` の `thinking_extra_ms` / `final_reduce_ms`。
応答が遅いと感じたら `thinking_extra_ms` を短く、話を奪われると感じたら長く。

## フェーズ7: 会話制御層 (実装済み・ルールベース)

ユーザー発話中の聞き手相づちと、応答生成前の定型thinking fillerは廃止した。
発話途中では音声を重ねず、相づちが必要な場合もSTT確定後の本応答の冒頭として
Conversation Plannerが文脈に合わせて生成する。

`ConversationControlLayer.listener_backchannel()` と `thinking_filler()` は古い呼び出し
との互換性のため残しているが、常に `None` を返し、音声は生成しない。

## 残っている制限

- 会話制御層はルールベース(小型LLM層は未導入。指示書17章の条件に従い、
  基本機能の安定後に検討)
- エコーガードは包絡相関のため、AIの声とユーザーの声が完全に重なった区間の
  分離はできない(回り込み+同時発話は割り込み語で対処)
- ループバック取り込みモードはTTS中ミュートが仕様として残る(自己帰還防止。
  DAVE直接受信が主経路のため影響は小さい)
- 複数人の同時発話は主発話者1人を選ぶ方式(指示書16章の初期方針どおり)
